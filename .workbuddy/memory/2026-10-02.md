### 关键设计决策

- 两个新功能**默认关闭**（沿用 Terminal 的 feature-gate 惯例），需设置里开启才出现入口。
- 入口可见性用 `[String: Bool]` 字典存（`缺失=显示`），新增入口不必每次加一个 Defaults 键。
- 代码格式化用独立 NSPanel（分栏编辑需要空间），密码生成器用 SwiftUI popover（紧凑）——
  按主人选择的不同形态实现。
- YAML 只做缩进重排，不猜测父子关系：零缩进的 key 按 YAML 语义视为同级，不强行嵌套。

### 后续：构建并替换本机已安装的 App

主人要求「构建并替换我安装的」。已用 Release + ad-hoc 签名构建并装入 `/Applications/Atoll.app`，
启动正常（PID 48154，无崩溃日志）。

踩到的坑（已写进 MEMORY.md）：
1. `CODE_SIGNING_ALLOWED=NO` 构建后再手工 `codesign --force --deep --sign -` 重签 →
   Sparkle.framework 嵌套结构被破坏，`codesign -v` 报
   "code has no resources but signature indicates they must be present"。
2. 正确做法是让 Xcode 用 `CODE_SIGN_IDENTITY="-"` 自己签，entitlements 里的
   `$(PRODUCT_BUNDLE_IDENTIFIER)` 才会被展开成 Sparkle 需要的 `com.Ebullioscopic.Atoll-spks/-spki`。
3. `osascript` 退出 App 报权限违例 -10004，改用 `killall Atoll`。

遗留影响（已告知主人）：ad-hoc 签名导致 cdhash 变化，TCC 权限需重新授权，Sparkle 自动更新不可用。
备份留在 `/Applications/Atoll.app.backup-20261002`。

## 增量需求：设置页中文化 + 磁盘图表 + 图表温度

### 1. 中文（走 xcstrings，不硬编码）

- 生效的目录是 `DynamicIsland/Localizable.xcstrings`（根目录那份**不在 target 里**）。
  sourceLanguage = en，zh-Hans 已有 1390/1601 条，说明主人机器跑的是中文界面。
- 新增 88 条 key（en + zh-Hans）专用名词 JSON/YAML/SQL/HTML/CSS/XML/JavaScript 标
  `shouldTranslate: false`。
- **写目录的可靠方式**：`json.load` 后 `json.dumps(..., ensure_ascii=False, indent=2,
  separators=(',', ' : '))`，**不要 `sort_keys=True`**（strings 里有个空串 key，排序会打乱
  既有顺序）。不排序时往返是字节级一致的，方便先做 dry-run 校验。

### 2. key 冲突坑（值得记住）

`String(localized: "Fair")` 在 `LockScreenWeatherManager.swift:505` 已被**空气质量等级**占用，
密码强度的 "Fair" 会共用同一个 key。给主目录填「一般」会把天气显示改坏。
解决：密码强度 5 个等级挪到独立字符串表 `DynamicIsland/PasswordGenerator.xcstrings`，
代码里改用 `String(localized: "Fair", table: "PasswordGenerator")`。
（顺带发现：空气质量 good/fair/moderate 整条在 zh-Hans 下**本来就没译文**，属于项目既有缺口，未动。）

### 3. 磁盘图表

代码早就完整集成了（`NotchStatsView.availableGraphs` 里已有 Disk 那张 DualGraphData），
只差 `showDiskGraph` 默认 `false` → 改成 `true`。已确认已安装 app 里**没有**残留的
`showDiskGraph` 偏好值，改默认值即可生效。5 张图时走既有的 3+2 布局。

### 4. 图表右上角温度

- 新 Defaults 键 `showTemperatureOnStatsCards`（默认 true），统计设置页「Graph Visibility」
  加了开关 + 搜索索引条目。
- `GraphData` 协议加 `temperatureText: String?`，`SingleGraphData`/`DualGraphData` 同步；
  `UnifiedStatsCard` 头部 `Spacer()` 后渲染。
- 取值按主人选的「各自温度 + SoC 兜底」：CPU 卡取 `statsManager.cpuTemperature`，
  GPU 卡取 `gpuDevices` 里最高的那个（没有则回落 CPU），内存/网络/磁盘直接回落 CPU/SoC。
  换算沿用 `cpuTemperatureUnit`（`.celsius` / `.fahrenheit`）与 `temperatureUnit.symbol`。
